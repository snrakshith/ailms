## M01-L01 — ML problem framing and baselines

### Core concept

Supervised models learn from targets; unsupervised methods discover structure; reinforcement learning learns decisions from rewards. A simple baseline establishes whether complexity is justified. Define the prediction time, unit and consequence of errors.

### Theory and reasoning

A prediction task has an observation time, target horizon, eligible features and an action. Baselines should reflect current operational behavior, not just arbitrary averages. A business metric assigns different consequences to different errors.

### Worked scenario

For churn prediction, define the observation window, target window and a majority-class baseline.

### Design and verification

A feature contains actual future inventory adjustment. Remove it or use only the planned value available at prediction time.

### Practice

Acceptance: Prediction horizon, input availability, split and cost of errors are explicit.

## M01-L02 — Train, validation, test and leakage

### Core concept

Training fits parameters, validation selects configurations, and test estimates final generalization. Preprocessing must be fit within training folds. Time, entity and group boundaries often matter more than random splitting.

### Theory and reasoning

Random splits assume exchangeable rows; repeated identities or time dependence violate this. Group splits prevent identity overlap; chronological splits simulate deployment. The test set should not influence feature, hyperparameter or threshold choices.

### Worked scenario

Split patient-level measurements by patient, not individual row.

### Design and verification

Duplicate rows appear across splits; group by source entity or deduplicate before split, and audit timestamp ranges.

### Practice

Design splits for transactions from repeat users and for chronological demand data.

Acceptance: No user overlap where required; test timestamps follow train timestamps for forecasting.

## M01-L03 — Preprocessing and feature pipelines

### Core concept

Imputation handles missingness; one-hot encoding maps categories to indicators; scaling changes numerical magnitude. ColumnTransformer applies different transforms by column and Pipeline keeps transformations together with the estimator.

### Theory and reasoning

An estimator pipeline composes fitting and transformation; ColumnTransformer applies separate numeric and categorical steps. Missing values, categories and scaling are learned from training data. Unknown categories need a deliberate fallback instead of schema crashes.

### Worked scenario

Combine median imputation, standardization and one-hot encoding for mixed customer features.

### Design and verification

Fitting the encoder before split leaks category information; put it inside the pipeline passed to cross-validation.

### Practice

Build a pipeline and predict a row with a missing number and unseen category.

Acceptance: Prediction succeeds with the same feature schema; fit uses training only.
