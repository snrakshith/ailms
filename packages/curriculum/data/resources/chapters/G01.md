## G01-L01 — Generative AI landscape and LLM fundamentals

### Core concept
Autoregressive LLMs predict next tokens; pretraining learns broad statistical patterns; instruction tuning and preference optimization adapt behavior. Generative output is probabilistic and may be unsupported even when fluent.

### Theory and reasoning
An autoregressive language model estimates p(token_t given previous tokens), not a database lookup or truth predicate. Pretraining learns statistical patterns; instruction tuning changes interaction behavior; inference generates tokens. Use deterministic software for exact rules and LLMs for flexible language tasks when errors are manageable.

### Worked scenario
Compare a language-model completion, embedding lookup and classifier on a support task.

### Design and verification
Using a free-form model for arithmetic or authorization introduces avoidable errors; delegate deterministic decisions to verified functions.

## G01-L02 — Tokens, tokenizers and context windows

### Core concept
Tokenizers convert text to integer IDs using schemes such as BPE, WordPiece or unigram. Special tokens represent boundaries or roles. Context limits include model-specific input and generated token accounting; token counts vary by model and language.

### Theory and reasoning
Tokenization maps text to integer IDs via a vocabulary and model-specific segmentation. Characters, words and tokens are not interchangeable; scripts and punctuation may change counts substantially. Context budget includes system messages, chat framing, retrieved evidence, tool schemas and generation allowance.

### Worked scenario
Compare token counts of code, English and multilingual text with a chosen tokenizer.

### Design and verification
Counting words underestimates chat overhead; measure rendered messages with actual tokenizer and check provider context limit separately.

## G01-L03 — Decoding, sampling and inference constraints

### Core concept
Greedy chooses a highest-probability token; temperature rescales logits; top-k limits candidate count; top-p retains a probability mass. Stops, output limits and constrained decoding influence completion behavior. Determinism is not guaranteed across serving systems.

### Theory and reasoning
Temperature rescales logits, top-k truncates candidates by rank and top-p keeps a cumulative probability mass. Greedy decoding selects highest score; low temperature may reduce variation but does not guarantee reproducibility across provider revisions or hardware. Sampling controls cannot guarantee truthful output.

### Worked scenario
Generate several responses under greedy and sampled settings and compare diversity.

### Design and verification
A consistently wrong answer looks reproducible; evaluate correctness and schema compliance, not just identical outputs.

## G01-L04 — Hugging Face Hub, Transformers and model selection

### Core concept
The Hub distributes model artifacts and metadata; Transformers provides model and tokenizer APIs. A model card describes intended use, limits and evaluation, but should be verified. Choose base versus instruction model, context, memory and license.

### Theory and reasoning
A model card should describe task, intended use, training data where disclosed, license and limitations. Base models differ from instruction-tuned models; architecture, tokenizer, context and memory requirements must match deployment. Pin immutable revisions; executable remote model code is a trust boundary.

### Worked scenario
Load a small permitted model and use its tokenizer and generation config.

### Design and verification
Comparing advertised benchmarks across different datasets or prompts misleads. Run the same local evaluation and disclose revision and hardware.

### Practice
Compare three model cards for task fit, license, size and known limitations.

Acceptance: Document exact revision and do not enable remote code without review.
