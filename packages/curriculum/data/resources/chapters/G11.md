## G11-L01 — Fine-tuning datasets, SFT and PEFT/LoRA

### Core concept
SFT trains on curated instruction-response examples. LoRA freezes base weights and learns low-rank updates to selected matrices, reducing trainable parameters. PEFT libraries implement adaptation; evaluate on a disjoint holdout and document base-model license.

### Theory and reasoning
SFT trains on instruction-response examples; PEFT freezes most weights and updates adapters. LoRA adds low-rank ΔW=BA, with r(d_in+d_out) trainable weights instead of d_in*d_out for a dense layer (bias/options may differ). Data quality, license and evaluation matter more than adapter size alone.

### Worked scenario
Inspect trainable parameter counts for a small model before and after applying LoRA.

### Design and verification
Using test examples in training or wrong chat format invalidates benchmark; inspect rendered examples and data provenance.

### Practice
Create a small licensed instruction dataset, split it, configure LoRA and plan a baseline comparison.

Acceptance: Report trainable parameters, data provenance and validation metrics.

## G11-L02 — QLoRA, quantization, serving and model optimization

### Core concept
QLoRA combines quantized frozen base weights with trainable adapters. Quantization reduces memory but may affect accuracy and requires compatible kernels. Serving optimizations include KV caching, batching, speculative decoding and runtime choices such as vLLM or llama.cpp.

### Theory and reasoning
Quantization reduces representation bits; QLoRA trains adapters over a quantized base model. Weight memory is roughly parameters×bits/8 before overhead; KV cache depends on layers, sequence, batch, KV heads and dtype. Throughput and quality depend on runtime and hardware.

### Worked scenario
Compare memory estimates for FP16 and 4-bit weights before adapter overhead.

### Design and verification
Estimating only weights undercounts memory and can cause OOM at long contexts; include KV cache, workspaces and concurrency.

### Practice
Estimate weight and KV-cache memory and benchmark a compatible serving configuration if hardware is available.

Acceptance: Document hardware, model, quality, throughput and actual peak memory.

## G11-L03 — Multimodal LLMs, diffusion apps and fine-tuning decisions

### Core concept
Multimodal models process inputs such as images and text using modality encoders or joint representations. Image generation uses methods including diffusion. Prompting changes input behavior; RAG supplies evidence; tools perform actions; fine-tuning adapts learned behavior. Evaluate each modality and rights/privacy constraints.

### Theory and reasoning
Multimodal models process text and visual/audio inputs using model-specific encoders and fusion. Document QA often benefits from OCR/layout plus grounded retrieval; image generation needs diffusion or other generative image models and separate safety/evaluation. Fine-tuning is not always preferable to retrieval or prompting.

### Worked scenario
Build a document-question-answering design combining OCR, vision and text retrieval.

### Design and verification
Using an image generator for factual document extraction is mismatched; test OCR fidelity and citation geometry instead.

### Practice
Design a benchmark and choose an architecture for document QA versus image generation.

Acceptance: Justify modality, evidence source, model choice, and privacy controls.
