## D02-L01 — Datasets, DataLoaders and training loops

### Core concept

Datasets define sample access; DataLoaders batch and optionally shuffle. A training loop runs forward, loss, backward and optimizer step. Evaluation uses model.eval() and disables gradient recording.

### Theory and reasoning

Training toggles dropout and batch-norm behavior, computes gradients and updates parameters; evaluation should use model.eval and no_grad/inference_mode. Epoch average must weight batch means by batch size, especially when last batch is small.

### Worked scenario

Train a classifier on generated features with batches and validation metrics.

### Design and verification

Averaging three batch means equally weights the final three examples too much; sum weighted losses and divide by count.

### Practice

Implement train_epoch and evaluate functions with sample-weighted losses.

Acceptance: Training changes weights; evaluation does not; batch sizes are handled correctly.

## D02-L02 — Normalization, dropout and early stopping

### Core concept

Batch normalization uses batch statistics in training and running statistics in evaluation; layer normalization normalizes within examples across selected dimensions. Dropout randomly masks activations during training. Early stopping selects a checkpoint from validation.

### Theory and reasoning

Dropout randomly masks activations during training; normalization can depend on batch statistics; weight decay penalizes or decays weights depending on optimizer. Early stopping chooses checkpoint by validation objective and patience.

### Worked scenario

Train a model with dropout and compare train/eval outputs on identical inputs.

### Design and verification

Saving `best=model.state_dict()` without copying may retain references to changing tensors; deepcopy or serialize checkpoint immediately.

### Practice

## D02-L03 — Mixed precision, GPUs and distributed training

### Core concept

Mixed precision uses lower precision where safe while retaining stability for sensitive calculations. Data parallelism replicates models and synchronizes gradients; model parallelism partitions computation or parameters. Profiling reveals actual bottlenecks.

### Theory and reasoning

Mixed precision reduces memory/compute for eligible operations but sensitive reductions often need higher precision. DDP replicates parameters and synchronizes gradients; global batch scales with workers and accumulation. Activation and optimizer memory exceed weight storage.

### Worked scenario

Estimate memory used by parameters, gradients and optimizer state before scaling training.

### Design and verification

Comparing asynchronous GPU timings without synchronization misreports throughput; warm up and synchronize around measurements.

### Practice

Compare throughput and validation loss on available hardware; if CPU-only, calculate memory estimates.

Acceptance: Report precision, device, batch size, throughput and numerical anomalies.
