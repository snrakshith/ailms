## G03-L01 — Embeddings, similarity and vector databases

### Core concept
Embeddings represent text or images as vectors. Cosine, dot-product and Euclidean similarity rank candidates differently depending on normalization. Vector stores index embeddings with metadata and support filtering; examples include FAISS, Qdrant, Chroma and pgvector.

### Theory and reasoning
Embeddings map inputs into vectors; cosine similarity normalizes dot product by lengths. Exact search is a baseline, approximate nearest neighbors trade recall for latency/memory. Model revision, dimensionality and distance metric define index compatibility; authorization filters must be enforced before exposure.

### Worked scenario
Embed short documents and compare semantic search with exact keyword search.

### Design and verification
Mixing embeddings from different model revisions or returning results before applying tenant filter yields wrong or unauthorized evidence.

### Practice
Implement brute-force cosine retrieval, then compare one vector backend.

Acceptance: Record model, dimension, metric and metadata filter behavior.

## G03-L02 — RAG ingestion, chunking and indexing

### Core concept
RAG retrieves external evidence at inference. Ingestion parses, cleans, chunks, embeds and indexes source content with provenance. Chunk size and overlap affect recall, noise and cost. Incremental indexing needs stable document IDs and deletion handling.

### Theory and reasoning
Chunking balances local coherence against retrieval granularity; overlap can reduce boundary loss while duplicating content. Stable IDs should encode document/version/span or content identity, and metadata links to authoritative source. Updates/deletions must remove stale chunks and invalidate caches.

### Worked scenario
Chunk a small set of policy documents, preserving section headings and source IDs.

### Design and verification
Appending revised chunks without deleting stale records creates conflicting evidence. Implement version-aware upsert and tombstone/cleanup.

### Practice
Build a chunker with stable IDs and test document update/deletion behavior.

Acceptance: Chunks trace to source spans and old versions can be removed.

## G03-L03 — RAG retrieval, reranking and answer grounding

### Core concept
Sparse search such as BM25 matches lexical terms; dense retrieval captures semantic similarity. Hybrid fusion combines signals; reranking scores candidate-query relevance more expensively. Answers should cite evidence and abstain when evidence is insufficient.

### Theory and reasoning
Dense retrieval captures semantic similarity; lexical retrieval catches exact identifiers; hybrid fusion combines ranks (e.g. reciprocal rank fusion). A reranker scores query-document pairs more precisely at extra cost. Generation should cite retrieved source IDs and abstain when insufficient evidence.

### Worked scenario
Retrieve top candidates for an acronym query, rerank and build a bounded context.

### Design and verification
A valid citation ID does not imply the cited text supports the claim. Evaluate entailment/faithfulness separately and show source snippets.

### Practice
Measure recall@k before/after hybrid retrieval and manually inspect citations.

Acceptance: Answer cites only available source IDs and abstains on unanswerable queries.

## G03-L04 — RAG evaluation and retrieval diagnostics

### Core concept
Retrieval metrics include recall@k, precision@k, MRR and nDCG; generation metrics include correctness, faithfulness and citation precision. Reference data and human review are necessary for reliable interpretation.

### Theory and reasoning
Retrieval recall, answer correctness, faithfulness and abstention measure different pipeline stages. Recall@k asks whether required evidence is retrieved; correct-looking answers may rely on pretrained knowledge and lack grounding. Unanswerable queries test safe refusal to invent evidence.

### Worked scenario
Compare two chunk sizes on a golden query-document set and identify retrieval versus generation failures.

### Design and verification
A single average conceals no-answer failures; stratify by answerability and report denominators and per-query traces.

### Practice
Create ten answerable and five unanswerable queries and report retrieval and answer metrics.

Acceptance: Show per-query evidence and abstention behavior, not just averages.
