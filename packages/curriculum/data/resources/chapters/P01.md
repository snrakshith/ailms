## P01-L01 — Model packaging, APIs and Docker

### Core concept

A deployable model includes preprocessing, weights, schema, dependency metadata and version identifiers. Docker images isolate user-space runtime; non-root users, minimal base images and health probes reduce operational risk.

### Theory and reasoning

A deployable model artifact includes model weights, preprocessing, input/output schema and version metadata. Containers should separate training from serving, run with minimal privileges and expose readiness distinct from liveness. Build artifacts once and promote immutable digests.

### Worked scenario

Package a scikit-learn pipeline behind FastAPI and build a local container.

### Design and verification

Loading untrusted pickle/joblib can execute code; restrict artifact origin and integrity verification.

### Practice

Build a container and run a health check and prediction contract test.

Acceptance: Container runs without training or secrets baked into image.

## P01-L02 — MLflow, data versioning and experiment tracking

### Core concept

MLflow tracks experiment runs and model metadata; DVC or object-store versioning can track data artifacts. A registry can record model versions and promotion decisions. Reproducibility requires immutable references and environment metadata.

### Theory and reasoning

Experiment tracking records run parameters, metrics, artifacts, code and data identifiers. Dataset versioning allows reproduction and comparisons; model registry promotion is a governance action with approval and rollback. Avoid logging raw sensitive training data.

### Worked scenario

Log two model runs and compare validation metrics and artifacts.

### Design and verification

Comparing runs trained on different splits conflates data change and model change; align manifests and evaluation datasets.

### Practice

Track a baseline and candidate; record why one is promoted.

Acceptance: Runs include code/data identifiers and reproducible configuration.

## P01-L03 — CI/CD, continuous training and DevSecOps

### Core concept

CI validates source, data contracts, tests and model metrics; CD promotes approved artifacts. Dependency, secret and container scanning reduce supply-chain risk; continuous training requires data and quality gates. Use staged deployment and rollback.

### Theory and reasoning

CI verifies code and artifacts; continuous delivery promotes tested versions; continuous training triggers controlled retraining with data/model evaluation. DevSecOps includes secret, dependency, static, image and dynamic checks plus artifact provenance. Gates should fail before deployment.

### Worked scenario

Create a pipeline with lint, unit tests, evaluation, dependency scan and approval before deploy.

### Design and verification

Treating retraining as automatic deployment can promote degraded models; require independent quality/safety gates and rollback.

### Practice

Design CI for a model service and simulate a failed quality threshold.

Acceptance: Failed tests or quality gates block release; artifacts are immutable.
