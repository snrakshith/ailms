## C03-L01 — Object detection: boxes, IoU, NMS and mAP

### Core concept
A detector predicts bounding boxes, class scores and confidence. Intersection over union (IoU) measures box overlap; nonmaximum suppression removes redundant detections in many pipelines. Average precision integrates a precision-recall curve under matching rules; mAP averages specified AP values.

### Theory and reasoning
IoU is intersection area divided by union. NMS sorts boxes by confidence and suppresses overlapping lower-score boxes within class; mAP integrates precision-recall per class at defined IoU thresholds. NMS does not equal mAP.

### Worked scenario
Calculate IoU for two boxes and inspect duplicate detections after NMS.

### Design and verification
Class-agnostic NMS removes overlapping different objects. Use class-aware suppression unless task explicitly needs otherwise.

### Practice
Implement IoU and class-aware NMS for a few predicted boxes.

Acceptance: Unit tests cover no overlap, exact match and different classes.

## C03-L02 — YOLO, Faster R-CNN, DETR and detection training

### Core concept
YOLO-style detectors typically predict dense detections in one pass; Faster R-CNN uses region proposals then classification/refinement; DETR treats detection as set prediction with matching. Accuracy, latency and small-object performance depend on setup.

### Theory and reasoning
One-stage detectors predict dense boxes/classes directly; Faster R-CNN uses region proposals then refinement; DETR predicts a set using matching and attention. Input scaling, annotation format, assignment and evaluation settings strongly affect results.

### Worked scenario
Benchmark a small detector with a fixed image size and a representative labeled set.

### Design and verification
Mixing normalized center-width-height with pixel corners corrupts training. Round-trip transform annotations and plot on image.

### Practice
Train or fine-tune a detector on a small custom dataset; profile latency and mAP.

Acceptance: Record architecture, data license, image size, IoU settings and hardware.

## C03-L03 — Semantic, instance and panoptic segmentation

### Core concept
Semantic segmentation assigns a class per pixel; instance segmentation distinguishes objects of the same class; panoptic segmentation combines stuff and thing labels. Dice and IoU quantify mask overlap with stated averaging rules.

### Theory and reasoning
Semantic segmentation assigns class per pixel, instance segmentation separates object identities, panoptic segmentation combines things and stuff. Dice=2TP/(2TP+FP+FN), IoU=TP/(TP+FP+FN). Empty-mask convention must be explicit.

### Worked scenario
Compare a predicted binary mask with ground truth and calculate Dice and IoU.

### Design and verification
Pixel accuracy can be high on mostly background images; report class-specific overlap and object-level failure cases.

### Practice
Implement mask metrics and evaluate per-class scores on synthetic masks.

Acceptance: Tests include empty masks and documented empty-class conventions.

## C03-L04 — U-Net, Mask R-CNN, SAM and foundation vision models

### Core concept
U-Net combines an encoder and decoder with skip connections; Mask R-CNN adds instance mask prediction to region-based detection; SAM-style models produce masks from prompts. Promptable models still need domain evaluation and possibly adaptation.

### Theory and reasoning
U-Net uses encoder-decoder skip connections for spatial detail; Mask R-CNN predicts masks for detected instances; promptable SAM generates masks conditioned on points/boxes or other supported prompts. Promptability does not imply semantic class prediction.

### Worked scenario
Segment objects from point or box prompts and compare against labeled masks.

### Design and verification
Comparing SAM with ground-truth box prompts to fully automatic U-Net is not equivalent; disclose prompt information and report separate tracks.

### Practice
Evaluate segmentation quality for difficult cases such as occlusion or small objects.

Acceptance: Report per-case IoU and prompts; note domain limitations.
