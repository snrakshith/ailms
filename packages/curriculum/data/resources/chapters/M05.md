## M05-L01 — Time series, forecasting and backtesting

### Core concept

Forecasting predicts future values with temporal dependence, seasonality and trends. Rolling-origin backtests preserve order; features must be available at forecast creation. Seasonal naive and exponential smoothing provide useful baselines.

### Theory and reasoning

A forecasting evaluation must mimic information available at forecast origin. Expanding windows increase training history while rolling windows forget old regimes. Seasonal naive uses the last corresponding seasonal value; horizon and aggregation matter.

### Worked scenario

Forecast weekly demand using last week's value and lagged features.

### Design and verification

Random split permits future leakage; use ordered windows and avoid centered rolling features.

### Practice

Build three expanding-window backtests and compare MAE to seasonal naive.

Acceptance: All prediction dates follow their training data; forecast horizon is constant.

## M05-L02 — Recommendation and learning to rank

### Core concept

Collaborative filtering learns from user-item interactions; content-based methods use item features. Two-stage systems retrieve candidates then rank them. Offline evaluation must avoid future interactions and account for exposure bias.

### Theory and reasoning

Collaborative filtering learns from user-item interactions; content-based methods use item attributes. Offline ranking should exclude already seen items and split by time or user as appropriate. Cold-start requires metadata or popularity fallback.

### Worked scenario

Recommend items by user-item similarity, then evaluate recall@k on held-out events.

### Design and verification

Including held-out interactions in similarity matrix leaks targets. Rebuild every feature from training interactions.

### Practice

Compare popularity baseline with nearest-neighbor recommendations.

Acceptance: Report recall@k for warm and cold-start segments separately.

## M05-L03 — Causal inference and experimentation

### Core concept

Random assignment supports estimating treatment effects under assumptions; observational causal inference requires identification assumptions such as exchangeability and positivity. Confounders affect treatment and outcome. A/B tests need prespecified metrics and stopping rules.

### Theory and reasoning

Random assignment helps identify treatment effects under assumptions including no interference. Define the estimand, primary outcome, guardrails, unit and analysis plan before seeing results. Confidence intervals represent uncertainty; repeated peeking changes error rates.

### Worked scenario

Design an experiment comparing two recommendation interfaces.

### Design and verification

Randomizing sessions when users see both experiences contaminates effects. Randomize by stable user or cluster, document interference.

### Practice

Specify unit of randomization, primary outcome, guardrail metrics and analysis plan.

Acceptance: Plan addresses interference, missing data and statistical uncertainty.
