## G07-L01 — Model Context Protocol (MCP) fundamentals

### Core concept

MCP standardizes how AI applications connect to external context and capabilities. A host coordinates clients; servers expose tools, resources and prompts. Transport and authorization depend on deployment and protocol revision. MCP does not grant permission automatically.

### Theory and reasoning

MCP connects a host application to servers through clients; servers may expose tools, resources and prompts, with capabilities negotiated by protocol. Resources expose contextual data, tools execute operations, prompts offer reusable message templates; the host owns user consent and authorization policy.

### Worked scenario

Design a server exposing read-only document search and a resource URI.

### Design and verification

Treating all MCP servers as trusted extensions permits instruction injection or excessive access. Validate capabilities, inputs and server identity.

### Practice

Acceptance: Explain the difference between tool execution and resource access.

## G07-L02 — FastMCP server and client development

### Core concept

FastMCP provides Python decorators and client abstractions for MCP. Typed function signatures expose tool schemas; resource and prompt definitions expose context or reusable templates. Local stdio is useful for development; remote deployments require transport-aware security.

### Theory and reasoning

FastMCP provides Python abstractions for MCP server and client development; transport and authentication depend on selected release. Tool discovery is a contract test, not proof of permissions. Read-only does not remove confidentiality risk.

### Worked scenario

Implement a local add or catalog lookup tool with FastMCP and invoke using a client.

### Design and verification

A public-looking resource returns private fields; return minimal approved schema and assert no internal keys in response.

### Practice

Create a read-only server, list tools and test valid/invalid invocation.

Acceptance: Discovery works and validation rejects malformed arguments.

## G07-L03 — MCP security, remote deployment and interoperability

### Core concept

Remote MCP servers need authenticated and authorized access, validated resource identifiers, timeouts and audit logging. Tool descriptions and results are untrusted content. Review server provenance, restrict outbound requests and pin protocol/library versions.

### Theory and reasoning

Remote MCP adds authentication, authorization, transport security and server identity concerns. Tool descriptions, resources and observations can contain adversarial text. Distinguish credential possession from permission to access a particular tenant or object.

### Worked scenario

Integrate a remote document server behind tenant-scoped permissions and explicit write approval.

### Design and verification

Passing user-supplied tenant as authorization context permits cross-tenant access. Bind tenant to verified identity and query constraints.

### Practice

Write a threat model and tests for cross-tenant requests and malformed resource IDs.

Acceptance: Unauthorized data is denied and logs omit secrets.
