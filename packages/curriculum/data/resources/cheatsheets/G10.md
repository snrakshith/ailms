# LLM and agent evaluation — quick reference

## Agent evaluation, datasets and LLM-as-judge
**Recall:** To detect or reduce position bias.

**Watch for:** Using the same model as generator and uncalibrated sole evaluator or exposing private traces to judges.

**Verify:** Report agreement, judge config and failure cases; do not use judge score alone.

## DeepEval for LLM and agent regression tests
**Recall:** Offline tests are stable and inexpensive; semantic judging is variable and may cost money.

**Watch for:** Confusing metric thresholds with universal quality standards or depending on live models for all unit tests.

**Verify:** Offline CI works without keys; judge-backed checks log thresholds and model.

## Ragas for RAG evaluation
**Recall:** Whether answer claims are supported by supplied context.

**Watch for:** Using an unavailable reference field or comparing metrics across changed evaluator configurations.

**Verify:** Report per-metric required columns, model and sample-level failure analysis.

## Promptfoo for prompt/model evaluation and red teaming
**Recall:** To detect regressions when templates or providers change.

**Watch for:** Storing API keys in YAML or attacking systems without authorization.

**Verify:** Report passing and failing cases and keep secrets in environment variables.

## Observability, traces, evaluation gates and cost
**Recall:** 95% of measured requests complete at or below that duration.

**Watch for:** Logging secrets or using aggregate metrics that hide high-risk failures.

**Verify:** Each metric has dataset, threshold, owner and failure action.
