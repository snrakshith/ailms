# Agent design patterns — quick reference

## Tool calling and tool-use agent pattern

**Recall:** The application/runtime, after validation and authorization.

**Watch for:** Executing arbitrary model-generated code or treating tool output as trusted instructions.

**Verify:** Invalid and unauthorized calls do not execute; errors are structured.

## ReAct, planning and action-observation loops

**Recall:** It chooses successive actions based on intermediate observations.

**Watch for:** Infinite repeated actions, stale observations and blindly following tool text.

**Verify:** Trace records action name, sanitized arguments, observation and termination reason.

## Reflection and evaluator-optimizer agents

**Recall:** When acceptance criteria pass, budget expires or escalation is needed.

**Watch for:** Self-critique can reinforce errors and add unnecessary cost.

**Verify:** Track improvement, revision count, failure rate and stop reason.

## Multi-agent systems and orchestration

**Recall:** They introduce coordination, latency, cost and failure complexity.

**Watch for:** Recursive delegation, conflicting writes and sharing unnecessary private context.

**Verify:** Each worker has narrow tools; merge resolves conflicts and records provenance.
