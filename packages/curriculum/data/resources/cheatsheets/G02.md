# Prompt and context engineering — quick reference

## Zero-shot, one-shot and few-shot prompting

**Recall:** No; decoding, infrastructure and model behavior also matter.

**Watch for:** Example contamination, order sensitivity and assuming one-shot makes output deterministic.

**Verify:** Report accuracy, format errors and example-selection criteria.

## Structured output, few-shot schemas and Pydantic

**Recall:** Application rules, data provenance and semantic constraints still need checking.

**Watch for:** Accepting parseable JSON as factual truth or silently coercing invalid values.

**Verify:** Invalid payloads fail safely; valid payloads serialize predictably.

## Persona prompting, reasoning prompts and prompt injection

**Recall:** They can be plausible but inconsistent with the actual facts or computations.

**Watch for:** Trusting a plausible explanation as evidence of correctness or exposing hidden reasoning or secrets.

**Verify:** Evaluate correctness and instruction adherence using external checks.

## Prompt serialization: ChatML, Alpaca and INST

**Recall:** No; they are model-family conventions with variations.

**Watch for:** Manually applying the wrong template, duplicating special tokens or concatenating untrusted messages as instructions.

**Verify:** Use the tokenizer's own template and document supported roles.

## Prompt versioning, testing and context engineering

**Recall:** Template, model configuration, schema, evaluation dataset and results.

**Watch for:** Changing model and prompt simultaneously makes attribution difficult.

**Verify:** Regression report compares one variable at a time and tracks cost and latency.
