# Mixed precision, GPUs and distributed training

**D02-L03 · Advanced · 135 min including practice**

## Learning objective
Explain memory/performance trade-offs and distributed data parallelism.

## Concept notes
Mixed precision uses lower precision where safe while retaining stability for sensitive calculations. Data parallelism replicates models and synchronizes gradients; model parallelism partitions computation or parameters. Profiling reveals actual bottlenecks.

## Worked scenario
Estimate memory used by parameters, gradients and optimizer state before scaling training.

## Common mistake
Assuming lower precision is always faster or forgetting effective batch size changes.

## Practice exercise
Compare throughput and validation loss on available hardware; if CPU-only, calculate memory estimates.

## Deeper theory and design

Mixed precision reduces memory/compute for eligible operations but sensitive reductions often need higher precision. DDP replicates parameters and synchronizes gradients; global batch scales with workers and accumulation. Activation and optimizer memory exceed weight storage.

## Debugging clinic

Comparing asynchronous GPU timings without synchronization misreports throughput; warm up and synchronize around measurements.
