# QLoRA, quantization, serving and model optimization

**G11-L02 · Advanced · 135 min including practice**

## Learning objective
Trade numerical precision, memory and quality deliberately.

## Concept notes
QLoRA combines quantized frozen base weights with trainable adapters. Quantization reduces memory but may affect accuracy and requires compatible kernels. Serving optimizations include KV caching, batching, speculative decoding and runtime choices such as vLLM or llama.cpp.

## Worked scenario
Compare memory estimates for FP16 and 4-bit weights before adapter overhead.

## Common mistake
Assuming four-bit storage equals complete runtime memory or every GPU supports every kernel.

## Practice exercise
Estimate weight and KV-cache memory and benchmark a compatible serving configuration if hardware is available.

## Deeper theory and design

Quantization reduces representation bits; QLoRA trains adapters over a quantized base model. Weight memory is roughly parameters×bits/8 before overhead; KV cache depends on layers, sequence, batch, KV heads and dtype. Throughput and quality depend on runtime and hardware.

## Debugging clinic

Estimating only weights undercounts memory and can cause OOM at long contexts; include KV cache, workspaces and concurrency.
