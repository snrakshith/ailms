# Structured output, few-shot schemas and Pydantic

**G02-L02 · Intermediate · 105 min including practice**

## Learning objective

Validate generated objects at the application boundary.

## Concept notes

Structured generation may use JSON schema constraints or tool arguments; few-shot examples illustrate semantic mappings. Pydantic validates typed Python objects, can reject extra fields and express constraints. Valid structure does not guarantee truthful content.

## Worked scenario

Extract an invoice object with required currency, total and item fields.

## Common mistake

Accepting parseable JSON as factual truth or silently coercing invalid values.

## Practice exercise

Define a strict Pydantic schema and test malformed, missing and extra fields.

**Acceptance criteria:** Invalid payloads fail safely; valid payloads serialize predictably.

## Deeper theory and design

Structured output separates syntax, schema and semantic correctness. Pydantic can reject unexpected fields and validate ranges; JSON Schema or constrained decoding may reduce invalid syntax where supported. Few-shot examples illustrate expected output but cannot replace validation.

## Debugging clinic

Valid JSON can have invented evidence or unsupported confidence. Add business checks and source verification after schema validation.
