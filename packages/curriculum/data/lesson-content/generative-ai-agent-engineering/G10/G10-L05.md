# Observability, traces, evaluation gates and cost

**G10-L05 · Advanced · 135 min including practice**

## Learning objective

Make LLM applications measurable and govern releases.

## Concept notes

Trace spans connect model calls, retrieval and tools; metrics include latency percentiles, token usage, cost, success and safety violations. Release gates compare quality and operational budgets against a baseline. Redact sensitive input/output and restrict trace retention.

## Worked scenario

Compare two RAG versions by recall@k, grounded answer rate, p95 latency and token cost.

## Common mistake

Logging secrets or using aggregate metrics that hide high-risk failures.

## Practice exercise

Define an evaluation dashboard and a CI gate for four metrics with rollback criteria.

**Acceptance criteria:** Each metric has dataset, threshold, owner and failure action.

## Deeper theory and design

Observability records requests, stages, model/tool selections, latency, token use and outcomes, with sensitive fields minimized. Evaluation gates compare candidate against baseline with explicit metrics and sample sizes. Production traces support triage but may contain private content.

## Debugging clinic

Averages hide tail latency and failures; use percentiles and per-slice results, redact prompt/response logs and limit retention.
