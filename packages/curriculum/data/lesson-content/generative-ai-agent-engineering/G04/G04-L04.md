# Agentic RAG and routing

**G04-L04 · Advanced · 135 min including practice**

## Learning objective
Allow a bounded agent to select retrieval tools and decompose queries.

## Concept notes
Agentic RAG uses a model or controller to choose retrieval actions, sources or subqueries. It can support multi-hop questions, but introduces extra latency, cost and failure modes. Authorization must be enforced outside the model.

## Worked scenario
Route a policy question to internal search and a product question to a catalog tool.

## Common mistake
Unbounded tool calls, cross-tenant retrieval or unnecessary agency for simple questions.

## Practice exercise
Compare deterministic routing with a bounded agent on a mixed question set.

**Acceptance criteria:** Report route accuracy, recall, tool count and cost proxy.

## Deeper theory and design

Agentic RAG uses a policy or model to choose whether/where/how to retrieve and when to finish. Deterministic routing is often cheaper and easier to audit; agent selection is helpful only if diverse requests benefit from adaptive retrieval. Tool permissions remain external.

## Debugging clinic

Agent repeatedly searches irrelevant indices and misses SLA; impose route/tool budget, timeouts and explicit terminal conditions.
