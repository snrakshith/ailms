# Streaming responses: SSE, chunks and cancellation

**G09-L02 · Intermediate · 105 min including practice**

## Learning objective
Stream incremental output safely and detect completion or failure.

## Concept notes
Server-sent events use text/event-stream and framed events; clients should handle partial content, error and completion events. Provider streaming, application streaming and UI rendering are separate layers. Cancellation and backpressure limit wasted resources.

## Worked scenario
Stream a mock token sequence using FastAPI StreamingResponse and detect disconnect.

## Common mistake
Assuming each chunk is valid JSON or leaking unsafe content before moderation completes.

## Practice exercise
Implement SSE events for delta, done and error and test a canceled client.

**Acceptance criteria:** Events are framed correctly; cancellation stops unnecessary work.

## Deeper theory and design

SSE uses UTF-8 events separated by blank lines, typically `event: delta` and `data: ...`. Streaming lowers time-to-first-token but not necessarily total latency. Cancellation should propagate to upstream generation; once headers sent, errors need in-stream semantics.

## Debugging clinic

A generator catches cancellation as generic error and keeps generating; ensure cleanup in finally and test canceled iteration.
