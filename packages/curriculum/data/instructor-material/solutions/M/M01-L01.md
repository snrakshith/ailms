# M01-L01 — ML problem framing and baselines: worked solution

## Problem

Write a problem statement for demand forecasting with an explicit baseline and business metric.

## Worked approach

Define next-7-day SKU demand from data available at cutoff midnight. Use prior same-weekday demand or trailing seasonal average as baseline. Train on older periods, validate on later periods, hold out latest period. Report MAE and shortage/overstock cost separately, noting unknown future promotions cannot be features.

## Failure analysis

A feature contains actual future inventory adjustment. Remove it or use only the planned value available at prediction time.

## Acceptance check

Prediction horizon, input availability, split and cost of errors are explicit.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)

- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
