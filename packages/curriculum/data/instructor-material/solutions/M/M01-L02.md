# M01-L02 — Train, validation, test and leakage: worked solution

## Problem

Design splits for transactions from repeat users and for chronological demand data.

## Worked approach

For repeated customers use GroupShuffleSplit or GroupKFold with customer ID; assert disjoint customer sets. For demand sort by timestamp, assign first 70% train, next 15% validation, last 15% test; add gap if labels overlap horizons. Fit transforms on train only and retain split manifests.

## Failure analysis

Duplicate rows appear across splits; group by source entity or deduplicate before split, and audit timestamp ranges.

## Acceptance check

No user overlap where required; test timestamps follow train timestamps for forecasting.
