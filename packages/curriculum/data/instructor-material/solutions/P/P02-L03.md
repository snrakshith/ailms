# P02-L03 — Cloud architecture, scaling and deployment trade-offs: worked solution

## Problem

Diagram architecture, forecast cost drivers and define rollback and recovery objectives.

## Worked approach

Draw AWS example with API gateway/load balancer, private compute (ECS/EKS or managed inference), IAM roles, encrypted S3/registry, secrets, VPC boundaries and telemetry. Estimate cost from requests×tokens or GPU-hours plus storage/egress; define RTO/RPO, canary rollback and load/failure tests. No cloud resources required for design.

## Failure analysis

Autoscaling workers without provider quota or budget limits amplifies failures/cost. Set concurrency, backpressure, retry budgets and alarms.

## Acceptance check

Architecture includes identity, encryption, limits, monitoring and failure isolation.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)

- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
