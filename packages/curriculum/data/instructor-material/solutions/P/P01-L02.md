# P01-L02 — MLflow, data versioning and experiment tracking: worked solution

## Problem
Track a baseline and candidate; record why one is promoted.

## Worked approach
Train baseline and candidate on same split; record seed, params, validation metrics, dataset hash and commit. In MLflow log parameters/metrics/artifact to local experiment or use offline JSON manifest. Promote candidate only when predefined gate and review pass, record rationale and prior version.

## Failure analysis
Comparing runs trained on different splits conflates data change and model change; align manifests and evaluation datasets.

## Acceptance check
Runs include code/data identifiers and reproducible configuration.

## Submission evidence
Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.
