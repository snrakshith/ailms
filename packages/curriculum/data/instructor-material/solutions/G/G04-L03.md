# G04-L03 — Self-corrective RAG and iterative verification: worked solution

## Problem

Implement a verifier with max three attempts and an explicit abstain state.

## Worked approach

Model state includes draft, evidence IDs, attempt, verification failures and status. Verify each claim; remove unsupported claims or retrieve targeted evidence, repeat at most three total attempts. Return validated subset or explicit abstention. Test permanent failure, first-pass success and correction success; assert attempt count <=3.

## Failure analysis

An unbounded verifier loop increases cost while never resolving a missing document. Add max attempts, evidence-change check and terminal failure state.

## Acceptance check

All runs terminate; unsupported claims are removed or flagged.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.
