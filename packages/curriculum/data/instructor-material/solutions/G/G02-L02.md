# G02-L02 — Structured output, few-shot schemas and Pydantic: worked solution

## Problem
Define a strict Pydantic schema and test malformed, missing and extra fields.

## Worked approach
Define BaseModel with ConfigDict(extra='forbid',strict=True), label Literal['billing','technical'], confidence float constrained ge=0/le=1. Use model_validate_json and catch ValidationError. Test valid JSON, missing label, extra field, string confidence and out-of-range value; cap retries and return controlled error.

## Failure analysis
Valid JSON can have invented evidence or unsupported confidence. Add business checks and source verification after schema validation.

## Acceptance check
Invalid payloads fail safely; valid payloads serialize predictably.

## Submission evidence
Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.
