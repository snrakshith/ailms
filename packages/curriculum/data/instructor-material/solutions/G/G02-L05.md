# G02-L05 — Prompt versioning, testing and context engineering: worked solution

## Problem

Create a prompt registry record with model revision, template hash and evaluation results.

## Worked approach

Store prompt_id, version, sha256(template), model revision, temperature, schema version and dataset hash. Compare baseline vs new prompt changing one variable; score accuracy, format failures, token counts, latency and cost. Promote only if gate passes; keep old version and rollback metadata.

## Failure analysis

Changing model and prompt simultaneously makes attribution impossible; isolate changes and repeat stochastic runs.

## Acceptance check

Regression report compares one variable at a time and tracks cost and latency.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.
