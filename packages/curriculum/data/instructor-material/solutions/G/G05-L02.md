# G05-L02 — ReAct, planning and action-observation loops: worked solution

## Problem

Build a mock loop that stops after four actions or a valid final result.

## Worked approach

Build loop with max 4 actions. Mock policy selects lookup, receives structured observation, then returns final result or next tool. Log action, redacted args, observation status and termination reason; test unknown tool, repeated failure and success. Cap total time and tool count.

## Failure analysis

A model repeats the same tool indefinitely; detect repeated calls, budget attempts and terminate with a useful error.

## Acceptance check

Trace records action name, sanitized arguments, observation and termination reason.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)

- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
