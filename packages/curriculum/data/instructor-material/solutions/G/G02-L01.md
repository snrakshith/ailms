# G02-L01 — Zero-shot, one-shot and few-shot prompting: worked solution

## Problem
Build a labeled holdout and compare all three prompt variants with fixed decoding settings.

## Worked approach
Build 20 labeled development/test texts with balanced categories, select examples only from development. Compare zero, one and three examples at same model/decoding settings. Parse output labels, count accuracy, invalid labels and per-class errors; run examples in alternate order and keep final test untouched until choices are frozen.

## Failure analysis
An example copies test content or contains incorrect labels, inflating performance or teaching wrong patterns. Audit overlap and label quality.

## Acceptance check
Report accuracy, format errors and example-selection criteria.

## Submission evidence
Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)
- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
