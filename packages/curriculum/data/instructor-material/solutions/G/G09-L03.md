# G09-L03 — LiteLLM gateway, routing and fallback: worked solution

## Problem

Create a gateway configuration template and test mock fallback behavior.

## Worked approach

Configure two approved model aliases using environment secrets; offline fake router attempts primary then fallback only on timeout/availability error. Record chosen alias, attempt, latency, token/cost metadata and sanitized error. Test primary success, fallback success, all unavailable and nonretryable rejection; live proxy validation is separate.

## Failure analysis

Fallback silently changes model capabilities or data region. Enforce equivalent policy constraints and disclose chosen model in trace.

## Acceptance check

Log selected model, failure reason, latency and cost metadata without secrets.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)

- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
