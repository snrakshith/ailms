# G07-L02 — FastMCP server and client development: worked solution

## Problem

Create a read-only server, list tools and test valid/invalid invocation.

## Worked approach

Implement `FastMCP('catalog')`, decorate `lookup(sku: str)` and restrict to public fixture records; run local transport. Use matching FastMCP Client or protocol inspector, list tools, call valid SKU and test invalid type/unknown SKU; record exact library version and transport. Offline pure lookup tests are distinct from actual MCP integration.

## Failure analysis

A public-looking resource returns private fields; return minimal approved schema and assert no internal keys in response.

## Acceptance check

Discovery works and validation rejects malformed arguments.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.
