# G08-L01 — Memory taxonomy: working, factual, episodic and semantic: worked solution

## Problem

Design a memory schema with type, source, timestamp, scope and expiry.

## Worked approach

Design record `{id,subject_id,type,content,source,created_at,expires_at,scope,consent}`; example factual preference, episodic prior project event, semantic glossary, working current draft. Define update/deletion and retention policy per type, exclude sensitive data by default. Audit retrieval purpose and ownership.

## Failure analysis

A temporary request becomes permanent preference without consent; distinguish session-only from persistable and permit correction/deletion.

## Acceptance check

Each entry has an explicit purpose and retention decision.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.
