# G04-L02 — Corrective RAG (CRAG): worked solution

## Problem
Implement a three-way retrieval-quality router with an offline fallback corpus.

## Worked approach
Use scores >=.8 strong, .4–.79 ambiguous and <.4 weak for illustrative mock data. Strong→use current evidence, ambiguous→merge/re-rank trusted corpora, weak→alternate approved corpus. Missing fallback→abstain. Test .9,.6,.1 and unavailable index; record route and source IDs. Thresholds are pedagogical, not calibrated.

## Failure analysis
A fallback leaks confidential queries to an external service or inserts stale documents. Authorize sources and redact/deny queries before retrieval; retain provenance.

## Acceptance check
Route tests cover strong, weak, ambiguous and unavailable fallback cases.

## Submission evidence
Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)
- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
