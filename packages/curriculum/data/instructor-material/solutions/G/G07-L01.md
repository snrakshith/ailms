# G07-L01 — Model Context Protocol (MCP) fundamentals: worked solution

## Problem
Diagram host/client/server and define schemas and permissions for two capabilities.

## Worked approach
Diagram host→client→server and define `get_policy(id)` read-only tool with strict ID, plus resource URI `policy://approved/{id}` with access check. List allowed capabilities, user scopes, error responses and transport trust boundaries. Explain read resource versus invoking a tool even if both return data.

## Failure analysis
Treating all MCP servers as trusted extensions permits instruction injection or excessive access. Validate capabilities, inputs and server identity.

## Acceptance check
Explain the difference between tool execution and resource access.

## Submission evidence
Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.
