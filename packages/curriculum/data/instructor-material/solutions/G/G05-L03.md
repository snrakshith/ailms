# G05-L03 — Reflection and evaluator-optimizer agents: worked solution

## Problem

Build a mock rubric checker and compare one-pass versus iterative outputs.

## Worked approach

Use draft answer and rubric requiring cited fact, correct label and schema. Mock evaluator returns missing criteria; optimizer repairs one missing item per revision. Stop on pass, no improvement or max 2 revisions. Compare pass rate and token/tool proxy against baseline, retaining failure reasons.

## Failure analysis

A judge gives higher score to verbose but wrong answers; anchor rubric to facts and run blind human review of disagreements.

## Acceptance check

Track improvement, revision count, failure rate and stop reason.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)

- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
