# G10-L04 — Promptfoo for prompt/model evaluation and red teaming: worked solution

## Problem

Create a local evaluation configuration for normal and adversarial inputs with pass criteria.

## Worked approach

Use local config with normal question, malformed response case and instruction-injection fixture; assert expected JSON schema or allowed label, no test secret, no protected action. Use mock/local provider when possible; pin tool version and record per-case status. External red-team runs are opt-in and use synthetic data.

## Failure analysis

Only evaluating happy paths overlooks injection and format failures; keep adversarial holdouts and fail closed on protected action.

## Acceptance check

Report passing and failing cases and keep secrets in environment variables.

## Submission evidence

Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)

- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
