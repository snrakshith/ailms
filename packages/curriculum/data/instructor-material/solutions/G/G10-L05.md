# G10-L05 — Observability, traces, evaluation gates and cost: worked solution

## Problem
Define an evaluation dashboard and a CI gate for four metrics with rollback criteria.

## Worked approach
Define gates for schema pass >=99%, grounded accuracy >=90%, p95 latency <=2s and cost/request <=budget on labeled fixture benchmark (illustrative thresholds). Assign owner, dataset/version and action to each. Simulate failed gate and block promotion; preserve trace IDs and rollback model version.

## Failure analysis
Averages hide tail latency and failures; use percentiles and per-slice results, redact prompt/response logs and limit retention.

## Acceptance check
Each metric has dataset, threshold, owner and failure action.

## Submission evidence
Include implementation or design artifact, test inputs and outputs, relevant dependency versions, and a short limitation statement. For external tools, report skipped integrations explicitly; a mock is not a live service test.

## Grading rubric (10 points)
- Correct mechanism or design: 4
- Evidence against acceptance criteria: 3
- Failure handling and boundary cases: 2
- Reproducibility and limitations: 1
